# Exercise sheet 11: Virtual Private Networks (33 points)

### Question 1 (10 points)
For each of the following use cases, indicate the technologies you would use to securely set up a local area network (LAN), choosing between VLAN and VPNs.

If your answer is a VPN, indicate where the endpoints should be -- where does the VPN tunnel start and end?

If your answer is VLANs, consider the L2 connection at the endpoints (e.g. the Ethernet cable connecting a server to the switch):
which VLAN tag(s) should this connection expose?

(If you need a refresher on how VLANs work, consider reading [this](https://www.networkacademy.io/ccna/ethernet/vlan-trunking).)

**1.1.** (2 points)
> You are hosting some service on your home server: you don’t want to
> expose it to the Internet, but you still need to access it remotely.

_Solution_:
VPN with endpoints on your laptop (tun/tap device) and in your home network.

**1.2.** (2 points)
> You work for a Certificate Authority, and want to access the CA
> administration panel running in an isolated internal network whilst you
> are at work.

_Solution_:
Still VPN (employee laptop to isolated network): VLANs do not provide authentication, nor logging for auditing purposes.

**1.3.** (2 points)
> A university needs to run, simultaneously, separate networks for student
> access, staff, and internal infrastructure like printers and information
> displays.

_Solution_:
VLANs: all these networks will share part of the same physical
infrastructure (trunk cables and switches).
VLAN-aware switches (usually located in [service closets](https://old.reddit.com/r/techsupportgore/comments/199yd61/this_is_the_networking_closet_for_a_building_in/) around the buildings) will strip the VLAN headers and only expose a particular
VLAN on a particular cable.
Ports in the offices will then see only traffic tagged for the staff-VLAN, printers for the printer-VLAN, and Eduroam routers/publicly accessible ports for the student-VLAN.

**1.4.** (2 points)
> The same university wants to provide remote access to their printers and
> plotters to students, so that they can place documents on the printing
> queues from home.

_Solution_:
VPN with an endpoint running inside the printers VLAN, the other endpoint on the student's laptops.

**1.5.** (2 points)
> In the same university wants to set up a server to receive emails and send
> the received attachments to printers.

_Solution_:
The server will need access to both the printer-VLAN and a VLAN with internet access.
This can be realized with either a single trunk cable (carrying tagged traffic for both VLANs),
and software configuration on the server to handle the VLANs
(e.g. on Linux: `ip link add link eth0 name eth0.100 type vlan id 100`),
or with two cables, one for each VLAN.

The suggested configuration can leak packets outside of the VPN in the case the DHCP server in your LAN is malicious.

### Question 3 (9 points)
The VPN market is continually expanding. Nowadays, you can choose
between a handful of VPN providers and, for less that 10 CHF/month,
connect to thousands of servers around the globe. But why should you pay
if a company offers to *pay you* 20 $/month to use their VPN service?
In 2016, Facebook developed a new app, called Facebook Research, that
installed in the users’ cellphone a VPN configuration, and asked the
users to trust a root certificate system-wide.[1]

[1] <https://techcrunch.com/2019/01/29/facebook-project-atlas/>

**3.1.** (2 points)
> VPNs are usually associated with privacy guarantees. Can we say the same
> about this particular service? Why?

_Solution_:
This particular VPN service does not provide privacy, as Facebook can intercept
and decrypt all traffic using this VPN (see following answer). VPNs provide
privacy guarantees privacy as long as the provider and the endpoints are
trusted.

That's a good reason not to trust most `free` VPNs.

**3.2.** (3 points)
> How can Facebook read your TLS data in plain text?

_Solution_:
Your data gets routed to the Facebook VPN servers. This enables Facebook
to mount a MitM attack and impersonate servers using certificates signed with
Facebook's key. These certs are anchored to the root certificate installed
in the phones, so the user’s browser will happily trust these unauthentic
certificates. Then, once the traffic reaches Facebook, they can decrypt
everything as they own the private keys.

**3.3.** (2 points)
> From a technical standpoint, is this an attack? If yes, which categories does
> it belong to?

_Solution_:
The user is willingly (maybe unknowingly) giving authorization to Facebook.
Facebook is capitalizing on the trust of its customers, and the monetary
reward, to breach the privacy of its users.
It is a matter of definition whether this is an "attack", or just "a service
offering". In any case, Facebook needs to run a MitM with the fake
certificate authority.

**3.4.** (2 points)
> When using a VPN, without any rogue root certificate installed, what data could
> your provider still register? What can it do with that data?

_Solution_:
Theoretically, they could keep your web navigation history in logs by recording
the SNIs of your TLS sessions, run analysis algorithms on them and even
sell them behind your back, or be compelled by governments to turn those data over.

Many providers say that they do not keep logs, but nothing stops them (or
any actor who can get their hands on their server) from logging.
VPN privacy ultimately relies on trust on the VPN provider.

### Question 4 (6 points)
WireGuard[1] is a modern VPN praised for its simple and elegant design.

[1] <https://www.wireguard.com/>

**4.1.** (2 points)
> The WireGuard protocol is connectionless: how are the handshakes
> handled? Is PFS guaranteed?

_Solution_:
A series of timers, both based on message counts and time, are used to
steer key renegotiation, handshakes and session termination.

The strict key rotation timers (`REKEY_AFTER_MESSAGES`,
`REKEY_AFTER_TIME`) and the ephemeral ECDH session key exchange
guarantee PFS.

**4.2.** (4 points)
> VPNs like WireGuard and IPsec implement mechanisms to avoid DoS attacks.
> What mechanism is used by WireGuard to avoid doing (expensive)
> cryptographic client authentication for new handshakes when under load?
> How does it differ from IPsec’s IKEv2?

_Solution_:
A WireGuard implementation can choose to respond with a cookie instead
of processing the handshake: the initiator will then use this cookie as
a key for computing HMACs of their message. The cookie mechanism of
IKEv2 is very similar to the one just described.

However, an important difference between the two is that Wireguard
requires an additional MAC on the handshake message — using the public
key of the responder as HMAC key. This allows the responder to stay
completely silent — not responding even with a cookie — unless the
initiator knows its public key. (Remember that “public” key do not need
to be publicly accessible, often they are not).

_Solution_:
Here is a commented version of [the demo script]
(https://git.zx2c4.com/wireguard-tools/plain/contrib/ncat-client-server/client.sh):

```bash
#!/bin/bash
# SPDX-License-Identifier: GPL-2.0
#
# Copyright (C) 2015-2020 Jason A. Donenfeld <Jason@zx2c4.com>. All Rights Reserved.

set -e # when any command fails, the shell immediately exits
[[ $UID == 0 ]] || { echo "You must be root to run this."; exit 1; } # Checks
# if you're root
exec 3<>/dev/tcp/demo.wireguard.com/42912 # Opens file descriptor 3 for reading and writing to the TCP/IP socket 42912 and opens a connection to demo.wireguard.com
privatekey="$(wg genkey)" # generate new private key
wg pubkey <<<"$privatekey" >&3 # generate public key from private key and write to file descriptor 3
IFS=: read -r status server_pubkey server_port internal_ip <&3 # from file descriptor 3 read status, server_pubkey, server_port and internal IP
[[ $status == OK ]] # check if status is okay, otherwise exit
ip link del dev wg0 2>/dev/null || true # delete previous configurations
ip link add dev wg0 type wireguard # add new interface called wg0
wg set wg0 private-key <(echo "$privatekey") peer "$server_pubkey" allowed-ips 0.0.0.0/0 endpoint "demo.wireguard.com:$server_port" persistent-keepalive 25
# set private key of interface wg0, authenticate connection to server, whitelist all IPs and set demo.wireguard.com as endpoint
ip address add "$internal_ip"/24 dev wg0 # forward all traffic with IP in range (internal IP)/24 to the interface
ip link set up dev wg0 # activate interface
if [ "$1" == "default-route" ]; then # if you want, you can give the script the option 'default-route' to use the demo server as VPN
  host="$(wg show wg0 endpoints | sed -n 's/.*\t\(.*\):.*/\1/p')" # gets IP address of demo.wireguard.com
  ip route add $(ip route get $host | sed '/ via [0-9]\{1,3\}\.[0-9]\{1,3\}\.[0-9]\{1,3\}\.[0-9]\{1,3\}/{s/^\(.* via [0-9]\{1,3\}\.[0-9]\{1,3\}\.[0-9]\{1,3\}\.[0-9]\{1,3\}\).*/\1/}' | head -n 1) 2>/dev/null || true
  # get routing information for demo.wireguard.com and add it to interface
  ip route add 0/1 dev wg0 # add all IP addresses from this range to the interface
  ip route add 128/1 dev wg0 # add all IP addresses from this range to the interface
fi
```
